## 障礙稽核方法與邊界

- 空間稽核使用與 live world 相同的建築、家具、工具設備及 tool markers 建立器。
- 從實際 Mesh／InstancedMesh 讀取 geometry bounding boxes、instance matrices 與 world matrices；保守 AABB 包含旋轉、桌面突出及設備側掛部分，沒有另外手填家具障礙清單。
- 只保留與站立模型高度重疊的障礙；忽略地坪基準以上 0.05 以下的薄飾條，以及全在頭頂以上的物件。
- 對每條完整線段計算與障礙 AABB 的最短距離，扣除藥師外接圓半徑；不是只檢查端點或稀疏抽樣。
- 同時檢查地板邊界、所有節點互通與停靠點對應工作區。缺障礙資料、無效角色尺寸、無效座標或缺停靠點不得回報通過。
- 這是靜態規劃與稽核，不是物理引擎或自由走動碰撞系統；R5 若改角色大小或使步態超過目前外接圓，須重新檢查最大動畫範圍。

桌面 587 個、手機 480 個模型障礙邊界均通過；全路網最小障礙淨空約 0.251，高於要求 0.1。
此數字已扣除角色半徑；額外剩餘約 0.151，不是角色中心距離。

## 測試與驗收資料

- pharmacy smoke suite：14 組通過，保留既有 22 工具桌面／手機導覽、routing、history、fallback、CSP、資源清理、鍵盤與 200% 等效 viewport 檢查。
- R3 包含 610 項斷言：桌面／手機所有 17 × 17 節點配對，以獨立 Floyd–Warshall 結果核對最短路徑；直接檢查實際模型頂點是否落在轉向外接圓內。
- 旋轉的 InstancedMesh 加在路線中途時必須判定阻擋；亦涵蓋缺停靠點、錯誤工作區、斷路、非有限座標、空障礙資料與零尺寸角色的失敗案例。
- Three.js vendor、portal/CSP invariants、SEO 無差異檢查通過。
- 跨專案 SW：11 個可載入 SW 通過；既有 migraine-tracker Workbox 產物仍因 `define is not defined` 略過，不計為通過。
- 桌面全景：83 draw calls／8,540 triangles；手機：83／6,876。尚未進行 Phase 3 優化。
