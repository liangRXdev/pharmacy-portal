# R5 — 藥師移動式探索

決策確認日期：2026-10-30（Asia/Taipei）。
狀態：使用者已於 2026-10-30 在影片與本機互動預覽交付後回覆「通過」，R5 驗收完成。尚未部署。

## 目標與使用情境

主要使用者為首次造訪的藥師同儕與教學合作對象，透過藥師移動探索工作領域與工具。
日常查找工具仍由首頁提供。正常 3D 模式沿用地圖導覽，文字清單僅作失敗備援。

## 已定案的互動

1. 點選工作區作為目的地。
2. 藥師沿中央通道移動，相機跟隨。
3. 到達該區預設停靠點後，顯示該區工具名稱與入口。
4. 點選工具設備或名稱，開啟既有介紹面板與工具連結。

移動範圍限定中央通道與預設停靠點。桌面與手機使用相同的點選目的地操作，
不提供自由走動、WASD、FPS、物理引擎或人群模擬。
採明確的路線與停靠點避免穿牆、穿櫃台，不引入通用碰撞系統。

## 中斷與特殊情境

- 移動途中點選另一區：立即取消原路徑，從當前位置重新規劃至新目的地。
- 操作保持可用，不鎖定輸入，也不排隊執行多個目的地。
- 快速連點：以最後一個目的地為準，不可在完成後返回已取消的舊目的地。
- `prefers-reduced-motion`：直接定位至目的地，省略移動與相機跟隨動畫。
- WebGL／模組失敗或 context loss：沿用文字備援，工具資訊仍可存取。

## 架構邊界與實作假設

- 保留 tools.json SSOT、原生 ES Modules、既有 world API、hash routing 與 browser history。
- 保留 DOM 工具介紹、原生地圖按鈕的鍵盤操作、手機觸控及既有 fallback。
- 不變更首頁零 3D 載入、CSP 或 SW ownership。
- 路線與停靠點是場景空間資料，不複製工具名稱、描述或 URL。
- R4 先定案靜態探索視角的距離與比例；移動速度、轉向與動態跟隨於 R5 以實際桌面／手機預覽調整並驗收。
- 返回全景、deep link 與 history 操作仍須可用；其角色定位呈現於 R5 預覽一併驗收。

## R2–R4 的前置空間規劃

使用者已確認：R5 的行走需求提前納入 R2–R3；R4 驗收角色、空間比例與取景。
整體樓板是否擴大依實際動線決定，不採整張場景等比例放大作為唯一處理方式。

| 階段 | 工作 | 驗收重點 |
| --- | --- | --- |
| R2 五區辨識與配置 | 重新檢視入口、Rx Hub、五區相對位置，讓工作區形成可探索的連續動線 | 五區仍可辨識，入口至各區的連通關係清楚 |
| R3 作業細節與路線定案 | 定義可行走通道、轉折與停靠點；移開阻路設備、拓寬狹窄處，必要時擴大樓板 | 以實際藥師模型體積確認通行及轉向空間；停靠點不與設備重疊，工具入口可操作 |
| R4 相機與視覺驗收 | 定案全景及較近的探索視角，檢視角色、設備與地圖的相對比例 | 桌面與手機全景能理解完整藥局；探索視角能看清藥師、設備及名稱，避免牆面或櫃台遮擋 |

R2–R3 的空間圖與 R4 的兩種靜態視角先由使用者驗收；角色動畫與動態相機跟隨仍在 R5 加入。
R4 的全景與探索視角須各提供桌面／手機截圖，不以單張縮小的桌面全景代替手機驗收。

## 驗收

驗收人：使用者。交付桌面／手機操作短影片與本地互動預覽，靜態截圖不能取代動態驗收。

| 情境 | 預期行為 |
| --- | --- |
| 正常到站 | 沿合法通道移動、相機跟隨、停在正確位置，再顯示該區工具 |
| 途中改目的地 | 從當前位置改走新路徑，舊目的地不再觸發到站或工具顯示 |
| 快速連點不同工作區 | 最後目的地生效，無排隊、跳回舊站或控制鎖住 |
| Reduced motion | 直接到站且顯示正確工具，不播放移動與跟隨動畫 |

自動測試須涵蓋路徑不穿越障礙、工具與目的地對應、中斷與最後目的地生效、
reduced-motion 定位，並繼續通過既有 routing、CSP、SW、fallback、資源清理與手機測試。
實機手機與視覺接受度由人工驗收，不以 SwiftShader 測試代替。

## 階段順序

R1 建築與空間配置 → R2 五區辨識與配置 → R3 作業細節與路線定案 → R4 全景／探索視角、光線與手機視覺驗收
→ **R5 藥師移動式探索與驗收** → Phase 3 效能驗證與調整 → Phase 4 發布檢查。

此決策取代原 handoff 中藥師僅為 ambient、不可互動的限制；其餘架構邊界持續適用。

## 本地實作與驗證紀錄

- `journey.js` 在既有路線圖上尋路。途中改站從當前所在邊的兩端比較可行路線，不吸附最近節點；相同目的地不重啟路徑，快速連點僅保留最後目的地。
- `pharmacist.js` 沿用同一角色模型，加入手腳擺動、轉向與輕微起伏。`world.js` 跟隨角色位置，抵達後切換分區／工具視角；移動期間保留五區目的地按鈕，隱藏工具名稱與介紹。
- 返回全景會在當前位置停止；下一次選區由該位置出發。Rx Hub 是可前往的中央停靠點。Deep link、back/forward 也遵循抵達後顯示工具；fallback 保留直接存取。
- 頁面隱藏會暫停步行，恢復後不補跑背景時間；切換 reduced motion 時立即到站。到站後鍵盤焦點移至地圖工具，關閉介紹仍回到原工具。
- 初始化先從實際場景幾何驗證路線，未通過即使用文字備援。步態的連續角度範圍包絡半徑為 `0.568969`，最小實測間隙為 `0.206031`，大於規格的 `0.1`；桌機／手機分別檢查 574／467 個障礙邊界。
- 分區與工具近景納入停靠後的實際角色進行遮擋檢查。工具近景改用偏側上方角度，22 個設備在桌機與手機均通過 raycast 可見性檢查。

已通過 `npm.cmd run test:pharmacy`：16 組既有 smoke、610 項空間斷言，以及 1,586 項 R5 斷言。涵蓋每條邊的三種途中位置至五站、禁止跨越捷徑、取消／改道／最後目的地、無效操作狀態保留、步態實際頂點包絡及離地、實際 RAF／相機／暫停恢復／清理。桌機與手機全部 22 工具、routing、CSP、fallback、SW 與資源釋放持續通過。

另外通過 portal 檢查、Three vendor 可重現性、SEO 重建無差異及 `git diff --check`。跨專案 SW 檢查通過 11 個可載入 SW；既有 `migraine-tracker` Workbox 產物因 `define is not defined` 跳過，未計入通過。
